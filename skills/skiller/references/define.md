# Define a skill

Use this phase to decide what the skill must do before choosing paths or writing files. Before defining or reviewing a definition, **always** consult the Agent Skills specification and best practices linked in `references/official-sources.md`. Consult the activation guide when drafting the description. If the sources are unavailable, disclose that limitation.

1. Ask for real use cases, example requests, source material, and previous corrections. Avoid defining a generic procedure without domain expertise or evidence.
2. Define one coherent capability: which requests should activate the skill, which similar requests should not, and what remains out of scope.
3. Identify inputs, expected outputs, environment constraints, permissions, and external actions that require confirmation.
4. Record the intended harnesses and project, user, or distribution scope as requirements. Do not choose discovery paths or installation mechanisms in this phase.
5. Propose a lowercase, hyphenated name and a specific description explaining what the skill does and when it should activate.
6. Define acceptance criteria with two or three requests that should activate the skill and at least one request that should not.
7. Present a concise definition for review. Resolve open behavioral decisions before authoring files.

The definition owns scope, activation, constraints, and success criteria. It does not choose a repository layout, divide content among files, create directories, or prepare publication infrastructure.
